## Compatibility and remaining findings

- Electron stays on major 44. [44.10.1 release notes](https://github.com/electron/electron/releases/tag/v44.10.1) describe fixes/performance/upstream backports; no required app API migration was found. [Electron versioning](https://www.electronjs.org/docs/latest/tutorial/electron-versioning) distinguishes major breaking changes. This is not a substitute for Windows testing.
- Vite remains at 8.3.3 and React plugin at 6.1.2: neither was implicated by this audit. We reviewed the available 8.3.5 patch and retained the working build chain to avoid unrelated updates. All declared Node engines remain compatible with the project's Node >=22.12.0 requirement.
- All 15 remaining moderate entries propagate from **minimatch GHSA-g3hv-75wg-m249** through electron-builder, asar, universal, glob, dir-compare and ejs/jake/filelist. Installed minimatch branches are 3.1.5, 5.1.9, 9.0.9 and 10.2.6. The advisory currently lists only 11.0.1 as fixed, with no same-major patch. [Advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).
- A global minimatch 11 override is unsafe: asar/dir-compare expect the old callable default export (removed in v9), while glob 7 uses RegExp members of `Minimatch.set`; v11 replaces these with Matcher objects and removes old APIs. [Official changelog](https://raw.githubusercontent.com/isaacs/minimatch/v11.0.1/changelog.md). Current electron-builder 26.18.0 still pins asar 3.4.1/universal 2.0.3 and requires minimatch ^10.2.5, so merely upgrading the builder would not solve this chain.
- The described minimatch amplification requires attacker-controlled glob patterns with optimizationLevel >=2. Reviewed builder/universal calls do not enable that option; app grouping does not call minimatch. This limits the observed exposure but **does not make the audit entries fixed**. Use trusted repository/build configuration; avoid third-party glob patterns and defer distribution packaging while deciding whether to await upstream compatible patches or separately approve a tested toolchain migration.
- inflight, rimraf, glob and boolean deprecation notices remain in upstream build/download tooling. Deprecation and a security advisory are different signals; neither is hidden, and devDependency status alone is not a safety argument.

The cloud used a writable npm cache at `/tmp/swire-npm-cache`. Clean install succeeded (357 installed packages), formatting passed, renderer and main-process TypeScript/build passed, **12 unit tests and 8 Chromium UI tests passed**. A separate launcher smoke test also started Vite on loopback port 5199 through the updated concurrently/wait-on chain, completed successfully and shut the server down. The new size-bound regression verifies a 31-item invalid reference list generates one `too_big` issue before per-element traversal.

Native runtime check remains **not executed**: after clean install there was no `node_modules/electron/dist/electron`. The explicit official installer command `electron_config_cache=/tmp/swire-electron-cache node node_modules/electron/install.js` exited 1 with `TypeError: fetch failed`; no sandbox approval was denied. This limits native runtime/version verification in this environment. Browser tests use system Chromium, not the Electron binary. Windows windows/dragging/capture/installer and real-provider behavior remain unverified.

After receiving this **new local-only patch**, a user may run `npm ci`, verify `npm ls electron zod concurrently shell-quote` against the versions above, then run `npm run dev:web` for an offline synthetic-data smoke test. Desktop testing also requires a downloaded Electron 44.10.1 runtime; if missing, run `node node_modules/electron/install.js` from the repository, then verify `npx electron --version` before `npm run dev`. If runtime download or version verification fails, stop the desktop launch and keep using the browser preview. Do not disable TLS, checksum or sandbox verification to make downloads work.

The previously pushed commit does **not** contain this fix yet. Before the update is delivered, keep remote AI unconfigured and use only trusted local/synthetic data for browser checks. With the patched lockfile and verified runtime, offline native smoke tests can proceed; this is not a blanket production/security sign-off.
